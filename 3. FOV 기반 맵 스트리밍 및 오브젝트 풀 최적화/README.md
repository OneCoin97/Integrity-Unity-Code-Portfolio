# FOV 기반 맵 스트리밍 및 오브젝트 풀 최적화

최대 38,093개의 블록 데이터를 가진 맵을 전부 GameObject로 유지하지 않고, 현재 유닛과 스킬의 FOV에 필요한 영역만 View로 생성하는 최적화 사례입니다. 맵의 원본 데이터는 유지하되 화면에 필요한 블록만 활성화해 대규모 맵의 오브젝트 수와 갱신 비용을 제한했습니다.

- [상세 설계 및 측정 결과](https://app.notion.com/p/3ba650b00a5c815ea9eedde4b3146122)

## FOV와 맵 스트리밍

일반적으로 `FOV(Field of View)`는 캐릭터의 시야 범위를 뜻합니다. 이 프로젝트에서는 유닛의 시야와 스킬 처리를 위해 블록 View가 활성화되어 있어야 하는 맵 좌표 범위를 공통적으로 FOV로 다룹니다. 맵 데이터 자체는 항상 유지하지만, 하나 이상의 FOV에 포함된 좌표만 실제 블록 GameObject로 생성합니다. 유닛이 이동하거나 스킬 범위가 바뀌면 전체 맵을 다시 만드는 대신 이전 범위와 새로운 범위의 차이만 View에 반영합니다.

## 갱신 흐름

1. 유닛의 이동이나 스킬 사용으로 FOV가 변경되면 해당 FOV가 새로 점유해야 할 맵 좌표를 계산합니다.
2. 여러 FOV가 존재할 때는 거리상 겹칠 수 없는 FOV를 먼저 제외하고, 실제로 중첩될 가능성이 있는 영역만 비교합니다.
3. 이전 점유 좌표, 새로운 점유 좌표와 다른 FOV가 계속 사용하는 좌표를 `HashSet`으로 비교해 새로 생성할 블록과 반환할 블록을 구분합니다.
4. `MapFovUpdateManager`가 FixedUpdate 요청 또는 즉시 갱신 요청을 받아 계산 결과를 View 적용 단계로 전달합니다.
5. 새로 보이는 좌표에는 풀에서 블록을 가져와 배치하고, 더 이상 어떤 FOV에도 포함되지 않는 좌표의 블록은 제거하지 않고 풀로 반환합니다.
6. 스킬 범위처럼 잠시 필요한 영역도 `TemporaryAreaFov`로 같은 계산 흐름에 참여시킨 뒤 사용이 끝나면 정리합니다.

전체 가시 영역을 매번 제거하고 다시 만드는 대신 이전 결과와 달라진 좌표만 반영하는 것이 핵심입니다. 블록 GameObject뿐 아니라 반복 계산에 사용되는 `HashSet`과 FOV별 상태 객체도 재사용해 이동 중 발생하는 GC 할당을 줄였습니다.

## 폴더 구성

- `1.Map Streaming`: FOV 후보 선별, 이전 및 현재 영역의 차집합 계산과 갱신 요청 관리
- `2.Object Pool`: 블록 인스턴스, 계산용 `HashSet`과 FOV 상태 객체 재사용
- `3.Integration`: 계산된 생성 및 제거 좌표를 View에 적용하고 스킬과 맵 수명주기에 연결

먼저 `1.Map Streaming/FovManager.cs`의 `setRange`에서 변경 영역이 만들어지는 과정을 확인하고, `MapFovUpdateManager.cs`와 `3.Integration/MapViewBlockStreamingExcerpt.cs`를 이어서 보면 계산 결과가 실제 블록 생성과 반환으로 연결되는 흐름을 파악할 수 있습니다.

포함된 코드는 실제 프로젝트의 FOV 시스템 중 물리 블록 스트리밍과 풀 재사용 흐름을 중심으로 선별했습니다. 별도의 오브젝트 데이터 스트리밍 분기와 프로젝트 전용 연결 코드는 제외했으며, `3.Integration`의 발췌 코드는 단독 실행보다 연결 구조 설명을 목적으로 합니다.
