# 모듈형 절차적 맵 생성 시스템

맵의 진행 구조를 나타내는 `MapLayoutData`를 먼저 생성하고, 완성된 설계도에 미리 제작한 Road와 Room 파츠를 조립해 실제 플레이 가능한 맵을 만드는 Data-Driven 절차적 생성 시스템입니다. 진행 경로 생성과 공간 표현을 분리했기 때문에 레이아웃 알고리즘을 바꾸지 않고도 파츠 데이터만 교체해 새로운 테마를 구성할 수 있습니다.

- [상세 설계 및 측정 결과](https://app.notion.com/p/5b4650b00a5c8274979281dbfa7f5094)

## 생성 흐름

1. `MapLayoutStageOption`과 시드로 방 종류, 경로 길이, 분기 수와 배치 조건을 결정합니다.
2. `MapLayoutGenerator`는 확장할 노드를 Queue로 관리해 가까운 분기부터 고르게 처리합니다. 게임이 한쪽 경로로 진행되는 선형 구조이기 때문에, 한 방향만 계속 깊어져 갈림길이 특정 구간에 몰리지 않도록 전체 확장 순서는 BFS 형태로 구성했습니다.
3. 각 입력 노드에서 다음 방까지 연결할 수 있는 개별 경로는 `RouteSolver`가 Stack 기반 DFS와 롤백으로 탐색합니다. 하나의 유효 경로가 확인되면 즉시 확정하고 다음 입력으로 넘어가므로, 필요한 첫 결과를 찾는 데 적합한 DFS를 사용했습니다.
4. 조건을 만족하지 못한 생성 결과는 버리고 다시 시도합니다. 한 번의 탐색 비용을 작게 유지한 채 최대 1,000회 반복하고, 끝내 생성하지 못하면 미리 준비한 기본 맵 데이터를 사용해 게임 진행 실패를 막습니다.
5. 레이아웃이 완성되면 `MapBuilder`가 분기를 Stack 기반 DFS 순서로 따라가며 각 노드 조건에 맞는 Road와 Room 파츠를 배치합니다. 플레이어가 실제로 경험할 한 경로를 끝까지 먼저 조립해 경로 내부의 공간 변화가 자연스럽게 이어지도록 한 순회 방식입니다.
6. 최종 `Map`에는 조립된 블록, 방과 트리거 데이터가 담겨 런타임 맵 시스템으로 전달됩니다.

같은 시드와 같은 파츠 데이터를 사용하면 레이아웃과 조립 결과를 다시 만들 수 있어 버그 재현에 활용할 수 있습니다. 같은 시드를 유지하고 `MapPart` 구성만 바꾸면 진행 구조를 유지한 채 외형과 공간 테마만 비교할 수도 있습니다.

## 폴더 구성

- `Main`: 레이아웃 생성, 개별 경로 탐색과 완성된 설계도에 맵 파츠를 조립하는 실행 코드
- `Assist`: 생성 옵션, 레이아웃 계약, Road 및 Room 파츠와 최종 맵 출력 데이터
- `Legacy`: 발췌 코드의 데이터 관계를 이해하는 데 필요한 최소 공용 계약
- `MapGenerationUsageExample.cs`: 시드와 스테이지 옵션을 설정하고 생성 실패 시 기본 맵을 사용하는 전체 호출 예시

`MapGenerationUsageExample.cs`로 외부 호출 흐름을 확인한 뒤, `Main/Layout/MapLayoutGenerator.cs`, `RouteSolver.cs`, `Main/Build/MapBuilder.cs` 순서로 읽으면 설계도 생성과 실제 맵 조립이 분리된 이유를 이해하기 쉽습니다.
